# Report Template Reference
Source: ORCH internal
Last refreshed: 2026-03-24

How to build styled HTML reports from markdown. Read by `/present-report`, `/present-deck`, and `/present-dashboard`.

## HTML Template Structure

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>{Report Title}</title>
  <link rel="stylesheet" href="deck-tokens.css">
  <link href="https://fonts.googleapis.com/css2?family=Inter:wght@400;600;700&display=swap" rel="stylesheet">
  <style>/* inline overrides */</style>
</head>
<body>
  <div class="report-header">
    <img src="{logo_path}" alt="Logo" class="logo">
    <div class="overline">{AGENT ATTRIBUTION}</div>
    <h1>{Report Title}</h1>
    <div class="dateline">{date} | {branch} | {repo}</div>
  </div>

  <div class="exec-summary">
    <p>{1-3 sentence executive summary}</p>
  </div>

  <div class="stat-strip">
    <div class="stat"><span class="stat-value">{n}</span><span class="stat-label">Label</span></div>
    <!-- 4-6 stat items -->
  </div>

  <nav class="toc">
    <h2>Contents</h2>
    <ul>
      <li><a href="#section-id">Section Name</a></li>
    </ul>
  </nav>

  <div class="section" id="section-id">
    <h2>Section Title</h2>
    <!-- tables, diagrams, content -->
  </div>

  <div class="report-footer">
    Generated by ORCH · {agent} · {date} · {token_count} tokens
  </div>

  <script src="https://cdn.jsdelivr.net/npm/mermaid/dist/mermaid.min.js"></script>
  <script>mermaid.initialize({startOnLoad:true, theme:'dark'});</script>
</body>
</html>
```

## CSS Classes Reference

### Layout Classes

| Class | Element | Description |
|-------|---------|-------------|
| `.report-header` | `div` | Top banner with logo, title, overline, dateline |
| `.overline` | `div` | Small uppercase text above the title (agent attribution) |
| `.dateline` | `div` | Date, branch, repo info below the title |
| `.logo` | `img` | Organization logo, max-height 48px |
| `.exec-summary` | `div` | Highlighted box for 1-3 sentence summary |
| `.stat-strip` | `div` | Horizontal row of 4-6 key metrics |
| `.stat` | `div` | Individual stat within stat-strip |
| `.stat-value` | `span` | Large numeric value |
| `.stat-label` | `span` | Small label below the value |
| `.toc` | `nav` | Table of contents with anchor links |
| `.section` | `div` | Top-level report section (gets `id` for TOC linking) |
| `.section-sub` | `div` | Nested subsection within a section |
| `.report-footer` | `div` | Bottom bar with generation metadata |

### Status Tag Classes

| Class | Color | Use For |
|-------|-------|---------|
| `.tag-ok` | Green (`--hds-success`) | Pass, healthy, compliant, complete |
| `.tag-warn` | Amber (`--hds-warning`) | Warning, partial, degraded, stale |
| `.tag-bad` | Red (`--hds-error`) | Fail, broken, critical, blocked |
| `.tag-info` | Blue (`--hds-info`) | Informational, neutral, pending |

Usage in HTML:
```html
<span class="tag-ok">PASS</span>
<span class="tag-warn">STALE</span>
<span class="tag-bad">FAIL</span>
<span class="tag-info">PENDING</span>
```

### Progress Bar Classes

| Class | Element | Description |
|-------|---------|-------------|
| `.progress` | `div` | Outer container (grey track) |
| `.bar` | `div` | Inner container (for multiple fills) |
| `.fill` | `div` | Colored fill segment; width set via `style="width:{pct}%"` |

```html
<div class="progress">
  <div class="bar">
    <div class="fill" style="width:85%; background:var(--hds-success)"></div>
  </div>
</div>
```

Color the fill based on value: green >= 80%, amber 50-79%, red < 50%.

### Diagram Classes

| Class | Element | Description |
|-------|---------|-------------|
| `.diagram` | `div` | Wrapper for a mermaid diagram |
| `.diagram-title` | `div` | Title above the diagram |
| `.diagram-caption` | `div` | Caption below the diagram |

```html
<div class="diagram">
  <div class="diagram-title">Component Architecture</div>
```

## Mermaid Integration Rules

### Must Do

| Rule | Reason |
|------|--------|
| Wrap in `<pre class="mermaid">` | Required by mermaid.js |
| Wrap in `<div class="diagram">` with title and caption | Consistent styling |
| Load mermaid script before `</body>` | Script must be last |
| Call `mermaid.initialize({startOnLoad:true, theme:'dark'})` | Match report theme |

### Must NOT Do

| Anti-Pattern | Problem | Correct Alternative |
|-------------|---------|---------------------|
| `<br/>` in node labels | Parsed as HTML, breaks mermaid | Use `\n` |
| `&lt;` `&gt;` in diagram | HTML entities not mermaid syntax | Use text descriptions or quote the label |
| `Signal<Trade[]>` unquoted | `<Trade[]>` parsed as HTML tag | `["Signal(Trade[])"]` or `["Signal<Trade[]>"]` |
| `&amp;` in labels | HTML entity | Use `and` or `+` |
| `&lpar;` `&rpar;` | HTML entity | Use `(` `)` directly |
| `-->` misinterpreted | Only a problem if inside HTML comments | Valid mermaid syntax, no issue in `<pre>` |
| Diagrams with 20+ nodes | Unreadable, slow render | Split into multiple diagrams |

## Post-Generation Verification Checklist

| Check | What to Verify | Tool |
|-------|---------------|------|
| **1. CSS & Styling** | `deck-tokens.css` linked, CSS variables resolve, Google Fonts present, core classes used | grep for class names |
| **2. Mermaid Diagrams** | No HTML entities in `<pre class="mermaid">`, script tag present, `mermaid.initialize()` called, diagram wrappers present | grep for `&lt;`, `<br/>` inside mermaid blocks |
| **3. Structure** | Valid HTML, all source sections present, tables have `<thead>`/`<tbody>`, TOC links match `id` attributes, footer present | HTML validator |
| **4. Content Quality** | Executive summary is 1-3 sentences, stat strip has 4-6 items, recommendations reference ORCH skills, no unresolved `{{TEMPLATE}}` variables | manual/grep |

Retry protocol: fix issue, re-run all 4 checks, max 3 attempts.

## Print Styles

Reports include `@media print` styles for clean PDF export via `Cmd+P`:

| Rule | Value | Purpose |
|------|-------|---------|
| Background colors | Preserved (`-webkit-print-color-adjust: exact`) | Keep dark theme in PDF |
| Page breaks | `break-inside: avoid` on `.section`, `.diagram`, `table` | No mid-table page splits |
| Stat strip | `flex-wrap: wrap` | Reflow stats on narrow paper |
| Mermaid diagrams | Pre-rendered as SVG | Print without JS |
| TOC links | Show URL after link text | `a::after { content: " (" attr(href) ")" }` |
| Font size | `--hds-font-size-base: 12px` | Fit more on printed page |
| Report footer | `position: fixed; bottom: 0` | Footer on every page |

## Report Stitcher Flow

```
1. Collect phase outputs (from workflow collect keys)
2. Map each output to its report-section
3. Auto-generate sections:
   - Title / header (from workflow report.title)
   - Executive summary (from overall status + key metrics)
   - Stat strip (from aggregated metrics)
   - TOC (from all sections)
   - Footer (from agent, date, token count)
4. Render collected sections into template slots
5. Apply deck-tokens.css
6. Run post-generation verification (4 checks)
7. Output final HTML
```
